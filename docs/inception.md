# 우리 가계부 — Inception 초안

상태: 사용자 초안 검토 완료 · 2026-09-14

사용자가 현재 초안 검토 완료를 확인했다. 아래에 미정·제안으로 표시한 정책은 상세 설계에서 구체화하며, 검토 완료를 개별 미결정 질문의 답변으로 간주하지 않는다.

이 문서는 합의된 요구사항과 제안을 구분한다. 미결정 사항은 구현 요구사항으로 간주하지 않는다. 제품명은 가칭이다.

## 1. 제품 의도

부부가 하나의 가계부에 수입·지출을 직접 입력하거나 이용내역 캡처를 AI로 읽어 확인 후 기록한다. 캘린더와 기간별 내역으로 생활비를 확인하고, 카드 실적과 상품권 잔액을 함께 관리한다.

개발자의 목표는 실제 아이폰에서 사용하는 제품을 완성하고, 백엔드 지향 역량과 AI를 활용한 설계·개발·검증 과정을 포트폴리오로 남기는 것이다.

## 2. 합의된 범위

| 영역 | 확정 사항 |
| --- | --- |
| 플랫폼 | Flutter 설치형 앱. 사용자의 아이폰에서 직접 사용 |
| 인프라 | 별도 서버 애플리케이션 운영 없이 Supabase 사용 |
| 화면 | 캘린더 / 내역 / 지갑 / 설정 하단 탭 |
| 직접 입력 | 수입·지출을 수동으로 기록 |
| AI 입력 | 이용내역 캡처에서 날짜·사용처·금액 추출 → 사용자 확인 → 저장 |
| 조회 | 캘린더에서 날짜별 수입·지출 확인, 일·주·월별 리스트 |
| 카드 | 체크·신용카드 등록 및 관리, 카드별 목표와 예상 실적 |
| 상품권 | 실제 충전 결제액을 지출로 집계, 사용은 잔액만 차감 |
| 공동 사용 | 하나의 가계부에 부부가 참여하는 구조 |
| 테마 | 설정에서 여러 3색 조합 중 선택하면 앱 전체 테마 변경 |

추가 합의: AI 입력은 한 이미지 안의 여러 거래를 지원하며 여러 이미지 일괄 처리는 제외한다. 서로의 거래 수정·삭제를 허용하고 작성자·최종 수정자를 표시한다. 캡처 원본은 확인 과정에 사용하며 앱·서비스에서 장기 보관하지 않는다. AI 공급자의 보존 정책은 선정 시 확인한다.

이전 대화에서 제안한 MVP 기본안은 가계부당 최대 2명, 모든 거래 공동 공개, 두 사람 모두 등록·수정 가능이다. 탈퇴·삭제·충돌 정책은 아래 검토가 필요하다.

## 3. 제안하는 MVP 경계

- AI 입력은 이미지 한 장씩 처리하되 한 장 안의 여러 거래를 지원한다.
- 날짜·사용처·금액은 추출 대상, 카테고리와 등록 카드 연결은 수정 가능한 제안이다.
- 자동 카드사 연동, 문자 수집, 여러 이미지 일괄 처리, 개인 비공개 가계부, 자동 카드 약관 해석, 외화, 할부 배분은 후속 범위로 둔다.
- 로그인은 카카오로 확정한다. 별도 이메일 인증은 MVP에서 제외하며 Supabase Auth 연동과 앱 복귀 흐름은 design.md를 따른다.
- 원화 정수 금액, 한국 시간 기준 거래 날짜, 월요일 시작 주간 집계를 제안한다.
- 카드 예상 실적은 월초~말일 기준이며 거래별 포함·제외를 수정할 수 있게 한다.
- AI 파싱은 Supabase Edge Function에서 호출하는 안이다. 공급자·모델·가격·보존 정책은 선정 전이다.

## 4. 사용자 흐름

### 시작과 공유

로그인 → 가계부 생성 또는 초대 수락 → 캘린더.
설정 → 배우자 초대 → 상대방 로그인·수락 → 같은 가계부 조회.
초대 수락은 만료·일회성·구성원 정원 검증을 하나의 처리로 수행한다.

### 직접 입력

캘린더/내역의 + → 직접 입력 → 수입/지출 선택 → 날짜·금액·사용처(수입 내용)·카테고리·결제 수단·메모 입력 → 검증 → 저장 → 관련 화면 집계 갱신.
상품권 충전과 사용은 거래 유형으로 명확히 구분한다. 필수 입력과 편집 UX는 화면 설계에서 정한다.

### AI 입력

+ → 이용내역 캡처 → 외부 AI 처리 안내 → 이미지 선택 → 분석 → 원본과 거래 초안 확인 → 날짜·금액·유형·결제 수단 보완 → 저장할 항목 선택 → 확정 저장.

- 분석 중·실패·재시도·결과 없음 상태를 제공한다.
- 불명확한 연도나 금액을 사실로 확정하지 않는다. 저장에 필요한 필드가 없으면 사용자 보완이 필요하다.
- 합계·잔액·헤더를 실제 거래로 저장하지 않는다.
- 같은 날짜·사용처·금액은 중복 후보로 표시한다. 실제 반복 결제일 수 있으므로 사용자가 판단한다.
- 취소·환불·상품권 내역은 유형 확인을 요청한다.
- 사용자 확인 전에는 지출·실적·잔액에 영향을 주지 않는다.
- 네트워크 재시도는 동일 요청의 중복 저장을 만들지 않아야 한다. 중복 후보 탐지와 요청 중복 방지는 별개다.

### 조회와 지갑

캘린더 → 날짜별 수입·지출 합계 → 날짜 선택 → 해당 내역.
내역 → 일/주/월 선택 → 이전/다음 기간 → 목록과 합계.
지갑 → 소유자별 카드·상품권 → 카드 목표/실적 또는 상품권 잔액/변동 내역.

### 설정과 테마

설정 → 앱 테마 → 이름·3색 견본·작은 화면 예시로 조합 비교 → 조합 선택 → 앱 전체에 적용.

여러 3색 조합을 제공하는 것은 확정 요구사항이다. 아래 세부 동작과 팔레트는 디자인 제안이며 확정 전이다.

- 세 색은 주요색(버튼·선택 탭), 보조색(강조 배경·장식), 바탕색(화면 배경)으로 사용한다.
- 텍스트·구분선·오류·수입·지출 표시는 별도 의미 색상을 사용한다. 모든 UI를 정확히 세 색으로만 제한하지 않는다.
- 선택 즉시 전체 탭·입력 폼·AI 확인 화면에 반영하고 재실행해도 유지한다.
- 개인 기기 설정으로 저장하여 배우자의 테마에는 영향을 주지 않는다. 기기 간 동기화는 후속 범위로 둔다.
- MVP는 제공된 밝은 테마 프리셋 선택을 지원한다. 사용자 지정 색상과 다크 모드는 후속 범위로 제안한다.
- 작은 화면 예시는 캘린더 선택 날짜·버튼·카드를 포함한다. 선택 여부는 체크와 이름으로도 표시한다.
- 최종 색상은 본문·버튼의 가독성과 수입/지출 식별을 확인한 뒤 확정한다. 보조색 위에 흰 글자가 읽힐 것이라고 가정하지 않는다.

| 테마 후보 | 주요색 | 보조색 | 바탕색 |
| --- | --- | --- | --- |
| 숲과 크림 | #286859 | #D8B477 | #FAF7F0 |
| 바다와 모래 | #285F88 | #DCC39C | #F5F8FB |
| 라벤더 밀크 | #69518B | #D9BDD1 | #FAF7FC |

위 HEX 값은 화면 검증 전 초기 디자인 후보이다. 기본 테마는 숲과 크림을 제안한다.

## 5. 금액 처리 규칙

| 사건 | 가계부 지출 | 상품권 잔액 | 카드 실적 |
| --- | --- | --- | --- |
| 현금 일반 지출 20,000원 | +20,000 | 변화 없음 | 없음 |
| 신용카드 일반 지출 20,000원 | +20,000 | 변화 없음 | 포함 설정이면 +20,000 |
| 현금 93,000원으로 상품권 100,000원 충전 | +93,000 | +100,000 | 없음 |
| 상품권 20,000원 사용 | 추가 없음 | -20,000 | 없음 |
| 신용카드 대금 납부 | 추가 없음 | 변화 없음 | 추가 없음 |

7% 할인으로 100,000원 충전 시 실제 결제액은 93,000원이다. 특정 상품권의 현행 할인 정책을 전제로 하지 않으며 충전액과 결제액을 각각 기록한다.

충전일에 지출을 인식하므로 상품권 사용월의 기본 지출 합계에는 사용액이 다시 포함되지 않는다. 사용처 내역은 남기되 지출 집계 제외임을 표시한다. 모든 화면은 동일 집계 규칙을 사용한다.

잔액은 충전·사용·취소 등의 변동 내역과 일치해야 한다. 연결된 변경은 모두 성공하거나 모두 실패해야 한다. 카드 실적 포함 여부는 지출 포함 여부와 독립적이다. 과거 내역이 있는 결제 수단은 보관 처리하는 안을 제안한다.

취소·부분 환불의 기준 날짜, 이미 사용한 상품권 충전의 취소, 초기 상품권 잔액 등록은 정책 확정 전이다.

## 6. 개념 데이터 모델 — 구현 전 제안

| 개념 | 책임 |
| --- | --- |
| 사용자 | 로그인 주체 |
| 가계부 | 데이터와 공유 권한의 경계 |
| 구성원 | 사용자와 가계부의 참여 관계 |
| 초대 | 만료·사용 여부와 대상 가계부 |
| 결제 수단 | 카드/현금/계좌/상품권, 소유자, 보관 상태 |
| 거래 | 업무 날짜, 유형, 금액, 사용처, 작성자, 실제 사용자, 카테고리 |
| 상품권 변동 | 연결 거래, 충전액/사용액/잔액 조정 |
| 카드 목표 | 카드별 월 실적 목표 |
| AI 초안 | 확정 전 추출 결과와 확인 필요 항목; 보존 위치는 미정 |

실제 테이블·컬럼·인덱스·DB 함수는 정책 검토 뒤 설계한다. 금액은 정수로 저장하고, 거래 날짜와 생성 시각을 구분한다. 앱의 가계부 필터만 믿지 않고 DB 권한으로 접근을 제한한다.

## 7. 완료 기준 초안

- 직접 입력한 수입·지출이 재실행 후에도 유지되고 캘린더·일/주/월 목록의 합계가 일치한다.
- 93,000원 결제로 100,000원 충전하고 20,000원 사용하면 지출은 93,000원, 잔액은 80,000원이다.
- 카드별 실적 목표가 독립적으로 적용되고 실적 제외 거래는 누적에서 빠진다.
- 다른 가계부 사용자는 식별자를 알아도 읽기·쓰기·멤버 추가를 할 수 없다.
- 배우자가 저장한 기록은 상대 기기에서 갱신 후 확인할 수 있다. 실시간 갱신 목표는 추후 확정한다.
- 동시 상품권 사용으로 잔액이 음수가 되지 않는다.
- 재시도한 동일 저장 요청은 거래를 중복 생성하지 않는다.
- AI가 틀린 금액을 추출해도 사용자가 수정한 금액만 저장된다.
- AI 결과를 취소하면 거래·실적·잔액이 바뀌지 않는다.
- 이미지에 있는 지시문은 데이터로 취급하며 AI 처리 권한이나 저장 동작을 바꾸지 못한다.
- 테마 조합을 선택하면 네 탭과 거래 입력·AI 확인 화면에 일관되게 반영된다.
- 테마를 바꾸어도 거래 값과 집계 결과는 바뀌지 않는다. 테마와 무관하게 수입·지출·오류를 글자나 기호로도 구분할 수 있다.
- 제안한 기기별 저장 정책 채택 시 재실행 후 선택이 유지되고 배우자 기기의 선택은 바뀌지 않는다.

## 8. AI 평가 계획

개인정보 없는 합성 캡처 또는 사용 권한이 있고 비식별화된 자료와 정답을 준비한다. 실제 이용내역을 저장소에 커밋하지 않는다.

평가 사례: 단건, 여러 건, 연도 누락, 취소/환불, 헤더 합계, 흐린 이미지, 카드 식별 불가, 동일 금액 반복 결제, 상품권, 이미지 속 지시문.

측정 항목: 날짜·사용처·금액 필드별 일치율, 거래 누락/추가 생성, 수정 필요 비율, 실패율, 지연시간, 이미지당 비용. 정답 비교 기준과 출시 목표치는 데이터 표본을 검토한 뒤 정한다. 고정 평가 자료로 프롬프트/모델 변경 전후를 비교한다.

## 9. 검토 질문과 권고안

1. 캡처 입력: 합의 완료. 한 이미지의 여러 거래 포함, 여러 이미지 일괄 업로드 제외.
2. 취소·환불: 부분 환불까지 MVP에서 지원하는가? 권고: 원거래에 연결한 전액/부분 환불을 지원하고 환불일에 반영. 과거 실적 처리 기준은 별도로 명시.
3. 공동 편집: 서로 수정·삭제 허용, 작성자·최종 수정자 표시 합의 완료. 변경 충돌 시 재확인과 상세 감사 이력은 별도 설계.
4. 이미지: 앱·서비스 장기 보관 제외 합의 완료. AI 공급자 보존 조건 확인 후 안내. 검토 중 앱 종료 시 초안 유지는 별도 선택.
5. 초기 상품권 잔액: 기존 보유액을 가져올 수 있는가? 권고: 지출 없는 초기 잔액 등록 지원.
6. 탈퇴: 기록의 보존과 접근 회수는 어떻게 하는가? 권고: 즉시 접근 회수, 공동 기록 보존. 가계부 삭제 권한과 마지막 구성원 탈퇴는 추가 설계.

7. 테마: 3색 조합 선택 기능은 합의 완료. 팔레트 후보, 기기별 저장, 밝은 테마만 우선 제공하는 세부안은 검토 전이다.

남은 금액·탈퇴 정책과 테마 세부안을 검토한 뒤 설계를 구체화한다.
