## 이번 수정

- T10 card_performance의 jsonb_agg 안에 sum을 중첩한 SQL은 호출 시 실패한다. 카드별 합산을 하위 쿼리로 분리했다. 이전 UI 모의 테스트와 함수 존재 테스트로는 이 결함을 검출하지 못했다.
- T12 충전 실제 결제액이 월 지출 합계에 빠져 있었다. voucher_topup을 지출 집계에 포함하고 카드로 결제한 충전도 인정 실적에 포함했다. voucher_use는 재집계하지 않는다.
- T01 직접 입력 확인/저장 진행 중 재확인 버튼을 잠가 중복 제출을 막았다.
- T05/T07 AI 검토 화면 복귀 후 조회를 갱신한다.
- 지갑 조회 실패가 무한 로딩으로 보이던 상태를 오류/재시도로 바꿨다.
- 저장 오류 원문과 전체 stack trace를 앱 화면/로그에 노출하던 코드를 제거하고 알려진 업무 오류만 반환한다.

새 migration은 기존 자료를 삭제하지 않는다. 로컬 migration up과 authenticated 역할의 실제 RPC 테스트로 카드 목표 300000, 실제 결제 93000, 사용 후 잔액 80000을 검증했다. 금융 조회 migration(20260919000000)은 원격 DB에도 적용했다.

## 후속 지갑 검증 보강

20260919010000 migration도 원격 적용 완료. 로컬 SQL 53개, Flutter 13개 테스트 및 정적 분석 통과. 원격에서는 migration 이력 일치를 확인했으며 사용자 실데이터 쓰기 테스트는 하지 않았다.

- 상품권 잔액은 클라이언트 행 조회 대신 서버 전체 합산 RPC로 계산해 API 반환 건수 제한의 영향을 없앴다.
- 카드 목표 저장 시 존재하지 않거나 보관된 카드, null 목표를 거부한다.
- 상품권 사용 환불은 같은 가계부/상품권의 유효한 사용 원거래를 요구하며, 누적 환불액과 날짜를 검증한다. 기존 RPC 서명도 새 검증을 거치도록 연결했다.
- 상품권 이벤트는 가계부 잠금 뒤 권한을 재검사하고, 날짜별 누적 잔액이 음수가 되는 과거 입력을 거부한다. 같은 날짜 안의 입력 순서는 판정하지 않는다.
- 회귀 테스트는 정상 부분 환불, 초과 환불, 원거래 누락, 구형 RPC 우회, 과거 사용, 없는 카드 목표를 검증한다.

## 최종 병합 전 리뷰

- 캘린더에서 다른 달의 날짜를 선택해도 현재 달만 조회하던 오류를 수정해 선택 월의 `[월 시작, 다음 월 시작)` 범위를 다시 조회한다.
- 수입 입력에는 현금·계좌만, 일반 지출 입력에는 상품권을 제외한 수단만 표시해 DB 계약과 UI를 일치시켰다.
- 상품권 잔액 조회 실패를 `0원`으로 표시하지 않고 로딩·실패 상태를 구분한다.
- 테마 선택의 중복 체크 아이콘을 제거하고 선택 칩 상태만 사용한다.
- README를 현재 구현, 로컬/원격 설정, 검증 명령, 보안 주의사항과 미완료 기능 기준으로 갱신했다.

## 남은 계약 차이 — 완료 처리 금지

1. T12: 초기 보유 잔액과 유상 충전이 UI/DB에서 분리되지 않음. 상품권 수단 생성과 첫 충전이 두 요청이라 부분 성공 가능. 멱등성, 수정/무효화와 잔액 연동, 충전 취소는 미완성이다. 이번 검증은 신규 사용 환불에만 적용되며 기존 refund 기록은 종류/연결의 신뢰성을 보장할 수 없어 일괄 지출 차감으로 바꾸지 않았다.
2. T10/T12: UI 상품권 충전에서 출금 수단을 전달하지 않아 해당 충전의 카드 실적 귀속이 없음. 이번 SQL 테스트는 출금 카드가 지정된 정상 RPC 계약을 검증한다. 카드 실적의 환불 귀속 월도 미완성이다.
3. T06: 선택 월 이동 조회는 연결했지만 날짜 칸별 합계, 일/주/월 목록·필터·페이지 이동 UI가 미완성이다. repository는 100건 한 페이지만 읽는다.
4. T04: 앱의 재시도마다 새로운 요청 ID를 생성한다. 응답 유실 재시도의 동일 요청 ID 유지가 필요하다.
5. T09: 설정에서 초대 코드 생성·수락, 구성원 확인, 탈퇴와 로그인 전 초대 링크 보존이 RPC에 연결됐다. 실시간 다른 구성원 변경 반영은 미완성이다. 배포 도메인/Associated Domains/App Links 검증이 필요하다.
6. T08: 앱은 fixture 화면만 연결됨. 함수의 가계부 소속 검사, 디코딩된 이미지 검증, 서버 호출량 제한, 공급자 timeout/비용/품질 검증이 부족하다.
7. T11: 소유자 이름이 모두 구성원으로 표시된다. 폼에서 결제 수단 등록 복귀 시 초안 보존이 부족하다.
8. 날짜 기본값이 기기 시간에 의존한다. 한국 기준 날짜 통일이 필요하다. 수입의 카드/상품권 선택은 차단했다.

42개 기존 SQL 테스트 대부분은 객체 존재/권한 검사다. 통과만으로 금액·동시성·외부 OAuth/AI 동작의 완료를 증명하지 않는다. 이번 실제 데이터 테스트도 전체 T12 계약 완료를 의미하지 않는다.
